# SourceID Liveness SDK — Flutter Plugin

A Flutter plugin for integrating the **SourceID Liveness Check** into your Flutter applications. It bridges the native SourceID liveness SDKs — [Android](https://github.com/EQua-Dev/liveness-expo) and [iOS](https://github.com/EQua-Dev/ios-single-liveness-expo) — which are built on [AWS Amplify Face Liveness](https://ui.docs.amplify.aws) (Amazon Rekognition Face Liveness).

---

## Features

* Real-time face liveness detection on Android and iOS
* Customizable UI — theme, title, primary color, branding footer
* Automatic AWS Amplify initialization (no host-app AWS setup required)
* Single-shot, promise-style API with typed error codes (including user cancellation)

---

## Architecture

```
Your Flutter app
      │  LivenessSdk.startLiveness(...)
      ▼
liveness_sdk (this plugin, method channel)
      │                          │
      ▼ Android                  ▼ iOS
liveness-expo (JitPack)     LivenessCheck (SPM/CocoaPods)
      │                          │
      ▼                          ▼
AWS Amplify Face Liveness (Amazon Rekognition)
```

## Installation

Add the dependency to your `pubspec.yaml`:

```yaml
dependencies:
  liveness_sdk:
    git:
      url: https://github.com/sourceidtechorg/sid-liveness-sdk-flutter.git
      ref: main
```

Then run:

```bash
flutter pub get
```

### Android setup

Add the camera permission to `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

The native SDK is resolved from JitPack automatically. If your app pins repositories in `settings.gradle` (`RepositoriesMode.FAIL_ON_PROJECT_REPOS`), add JitPack there:

```kotlin
dependencyResolutionManagement {
    repositories {
        google()
        mavenCentral()
        maven { url = uri("https://jitpack.io") }
    }
}
```

### iOS setup

Enable Flutter's Swift Package Manager support if you haven't already:

```bash
flutter config --enable-swift-package-manager
```

Add the camera usage description to `ios/Runner/Info.plist`:

```xml
<key>NSCameraUsageDescription</key>
<string>We use the camera to verify that you are a live person.</string>
```

Set the iOS deployment target to at least 14.0 (in Xcode's Runner settings, and `platform :ios, '14.0'` in your `Podfile` if you have one).

**One-time plugin approval:** the AWS SDK dependency uses a Swift build plugin (`SmithyCodeGeneratorPlugin` from `smithy-swift`). The first time you build, Xcode asks you to **Trust & Enable** it — open `ios/Runner.xcworkspace` in Xcode, build once, and approve the prompt. On CI (no GUI), pass the per-invocation flags instead:

```bash
xcodebuild ... -skipPackagePluginValidation -skipMacroValidation
```

**Troubleshooting — "requires minimum platform version 14.0 … but this target supports 13.0":** Flutter's generated plugin package (`ios/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage/Package.swift`) is supposed to inherit your app's deployment target. Some Flutter versions fail to bump it; if you hit this error even with `IPHONEOS_DEPLOYMENT_TARGET = 14.0`, patch the generated file (it is regenerated by `flutter build`, so re-apply as needed):

```bash
sed -i '' 's/\.iOS("13\.0")/.iOS("14.0")/' ios/Flutter/ephemeral/Packages/FlutterGeneratedPluginSwiftPackage/Package.swift
```

## Prerequisite: a liveness session ID

A liveness check runs against a **session** created server-side with Amazon Rekognition (`CreateFaceLivenessSession`). Your backend (e.g. the SourceID gateway's `POST /liveness/generate-liveness-url`) creates the session and returns the `sessionId`; after the flow completes, your backend fetches the confidence result (`GetFaceLivenessSessionResults`).

The SDK **never scores the check itself** — it runs the capture flow. A success result means the user completed the flow; your backend decides pass/fail from the session results.

## Usage

```dart
import 'package:liveness_sdk/liveness_sdk.dart';

final livenessSdk = LivenessSdk();

Future<void> verifyUser() async {
  try {
    final result = await livenessSdk.startLiveness(
      sessionId: sessionIdFromYourBackend,
      region: 'us-east-1',
      config: LivenessUIConfig(
        hideBranding: false,
        customTitle: 'Verify Your Identity',
        theme: 'dark',
        primaryColorHex: '#0A84FF',
      ),
    );

    // The capture flow completed — verify the result server-side.
    print('Liveness flow finished: ${result.message}');
  } on LivenessException catch (e) {
    if (e.isCancelled) {
      // The user backed out of the flow.
    } else {
      // Permission denied, expired session, network failure, ...
      print('Liveness failed [${e.code}]: ${e.message}');
    }
  }
}
```

## API reference

### `LivenessSdk.startLiveness({sessionId, region, config})`

Launches the full-screen liveness flow. Returns a `Future<LivenessResult>` that completes when the flow finishes. Exactly one outcome is delivered per call.

### `LivenessResult`

| Field | Type | Description |
| --- | --- | --- |
| `status` | `String` | `"success"` when the capture flow completed |
| `message` | `String` | Human-readable outcome description |
| `isSuccess` | `bool` | Convenience getter for `status == 'success'` |

### `LivenessUIConfig`

| Property | Type | Default | Description |
| --- | --- | --- | --- |
| `hideBranding` | `bool` | `false` | Hide the "Powered by SourceID" footer |
| `customTitle` | `String?` | `null` | Title shown above the camera view |
| `theme` | `String` | `'light'` | `'light'` or `'dark'` |
| `primaryColorHex` | `String?` | `null` | Accent color, e.g. `'#0A84FF'` |

### `LivenessException`

Thrown when the flow fails or is cancelled:

| Code | Meaning |
| --- | --- |
| `CANCELLED` | The user backed out of the flow (`e.isCancelled == true`) |
| `INVALID_ARGUMENTS` | `sessionId`/`region` missing or empty |
| `NO_ACTIVITY` / `NO_VIEW_CONTROLLER` | No UI available to present the flow from |
| `IN_PROGRESS` | Another liveness flow is already running (Android) |
| `LAUNCH_FAILED` | The native flow could not be started (Android) |
| `LIVENESS_ERROR` | The detector failed — network error, expired session, permission denied, Amplify configuration failure, ... |

## AWS configuration

Both native SDKs bundle SourceID's default Amplify (Cognito) configuration and initialize Amplify automatically. If your app already configures Amplify itself, the SDKs detect and reuse your configuration. To use your own Cognito pool, provide your own `amplifyconfiguration.json` (Android: `res/raw/`, iOS: app bundle).
